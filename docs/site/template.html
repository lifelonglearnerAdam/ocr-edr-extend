READ IN THREE LAYERS

第一次看这个项目，先理解这四件事

2 分钟看结论 → 10 分钟看方法与对照 → 按链接检查证据和复现。

1. 我们要解决什么问题？

OCR 解析器将图像转为 LaTeX／HTML，但可能识别错文字、遗漏内容或破坏结构。我们希望小模型读源图与当前结果，找到有依据的局部修复，并在不误改正确内容的前提下决定何时停止。

最终研究问题不是“能不能多跑几轮”，而是：在固定模型与预算下，独立核验和控制策略能否得到更好的修复收益—误改风险—调用成本权衡，并在未知解析器上保留？

2. 核验与修复有什么区别？

Verifier回答“哪里疑似错、是什么错误”；Refiner回答“改成什么”。一个模型可以判断出数值不对，却把正确数值写到错误单元格。

因此学长的 98.17% 联合诊断准确率和我们的 TEDS 修复分数回答不同问题，不能直接比较，也不能解释为“98.17% 的表格都能修好”。接入后的真实下游收益要另做实验。

3. 为什么保留失败结果？

字面 JSON 示例让基座更容易遵守动作格式，却使训练后模型复制模板或错位编辑。去掉示例后，all 能删掉多数受控重复行，但仍不会修数值或跨度。

保留两种条件才能知道进展来自什么：提示匹配、错误类型与保持目标都影响行为。只展示最高分会掩盖尚未解决的能力和风险问题。

4. “完成”具体指什么？

“381 步训练完成”表示优化器执行与检查点已核验；“评估完成”表示全部输入计入分母；“参考全修复”表示相对指定标注达满分。

这些都不等于独立视觉正确、正式基准提升、未知解析器泛化或论文创新。当前五方向整体系统尚未完成，页面分别标记已经执行的实验与下一步假设。

常见术语和指标：读结果时如何避免误解
术语在本项目中的意思不能单独证明什么
Base / SFT / LoRABase 为原模型；SFT 用目标样例监督训练；LoRA 只更新较少适配器参数。loss 下降不能证明修复收益。
Preservation正确候选的目标动作是 stop，用于学习保持。全拒绝或全 stop 也能零退化，不表示模型会修。
TEDS / TEDS-S对 HTML 表格与参考的树结构编辑相似度；TEDS-S 侧重结构，通常取 0–1，越高越一致。弱参考可能有表示歧义；规范化可能掩盖原渲染问题。
Core CDM公式渲染后的符号／视觉匹配指标；本项目按固定官方核心实现计算。不是源码字符串相同，也不是完整端到端文档基准。
全修复 / 退化初始参考非满分→满分；初始满分→非满分。当前表格分母分别为 71 与 32。两个分母不同，不能只比较计数。视觉判断另记。
文档等权 / bootstrap一篇文档的变体先平均，再让文档等权；按文档配对重采样。开发区间不提供低风险保证或多 seed 稳健结论。
Region / DOM 地址候选内的上下文范围／行列单元格索引；随当前候选重新计算。不是跨样本通用标签；地址合法不保证位置正确。
NF4 / 8 GiB四位权重存储，让本地卡能训练；计算、非量化层 dtype 明确记录。不同精度基座不能直接配对归因，低显存不等于质量改善。
Train / dev / calibration / locked训练、模型开发、验收校准、冻结最终验证使用不同来源角色。看过的开发图不能事后称作 untouched test。
