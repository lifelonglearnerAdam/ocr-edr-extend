# First controlled formula diagnostic: 2026-10-02

The first real-model experiment completed on the standalone paper project. An untrained, locally cached Qwen2-VL-2B model ran 80 unique inference calls on 20 paired cases. No teacher API, training, Jev calls, official benchmark scores or Note-project data were used.

## Main observation

Source-only repair fixed 7/8 initial errors; adding the candidate rendering fixed 2/8. A second turn added no fixes. All conditions preserved the visual content of the 12 initially correct/equivalent inputs in this diagnostic.

| Condition | Errors fixed / 8 | Correct/equivalent inputs changed to incorrect / 12 | Exact-raster proxy | Mean generation seconds |
| --- | ---: | ---: | ---: | ---: |
| `unchanged_0` | 0 | 0 | 60% | 0.00 |
| `source_only_1` | 7 | 0 | 95% | 2.23 |
| `with_render_1` | 2 | 0 | 70% | 3.17 |
| `fresh_render_2` | 2 | 0 | 70% | 6.34 |
| `stale_render_2` | 2 | 0 | 70% | 6.35 |

These are same-renderer exact-raster proxies on four synthetic templates, with both ordinary and altered source expressions, not CDM or VisFix. The 20 cases derive from eight source images and four original templates; no statistical/generalization claim follows. This result does not reproduce or refute the trained OCR-EDR model.

## Failure analysis

- On both exponent directions (`c002`, `c014`), source-only proposals followed the source; rendered proposals retained the wrong input exponent. This is consistent with candidate anchoring or image-role confusion, but neither mechanism is established by this experiment.
- The candidate-rendering condition also retained incorrect sum/integral limits in several cases. It did repair both fraction-operator directions and the altered sum source `c018`.
- Source-only `c018` returned `(135,135),(855,450)` instead of a formula. MathText successfully renders that string, so the syntax gate allowed it. Rendering success cannot establish correctness or even task validity.
- All 80 unique responses omitted the requested `<latex>` wrapper. The extraction fallback admitted their raw text. The report counts wrapper violations separately; it does not treat them as successful contract compliance.
- Fresh versus stale images actually differed in only 2/20 second-turn inputs (`c005`, `c018`). Their final predictions were the same. Most remaining inputs provide no useful fresh-render contrast. A larger set with genuine first-turn edits is necessary.
- Normalized string exactness was 75% for source-only and 60% for the other model conditions, versus exact-raster proxies of 95% and 70%. Benign spacing/bracing explains the difference; neither metric is a general equivalence test.

The [case image](../../experiments/artifacts/formula-pilot-20261002/diagnostic_cases.png) shows six representative cases. The source, initial prediction, source-only proposal and with-render proposal were visually inspected in this comparison.

## Decision for the next step

Do not advance an untrained two-image repair prompt into expensive RL on the strength of this pilot. Keep source-only repair as an essential baseline. First separate image-role interpretation, local error detection, constrained edits and acceptance quality on a small real formula/table development set. Recheck source-versus-candidate ordering and local visual evidence as exploratory controls; freeze a new protocol before evaluating any holdout.

Teacher distillation, GRPO and Jev remain untested. The five [hypotheses and stopping rules](HYPOTHESES.md) guide subsequent decisions. Formula-versus-text superiority and cross-parser transfer remain open.

## Reproducibility and cost

Model snapshot: `895c3a49bc3fa70a340399125c650a463535e71c`. Inference code commit: `07fd31cbb4dc19184248845c5bad13a6870dcd11`, clean when the run began; file hashes are recorded. Greedy bfloat16 inference used CPU, 8 Torch threads, SDPA, the slow image processor, image limits of 100352–200704 pixels and 128 maximum output tokens per call. No output reached the token cap.

The batch ran from 21:59:24 to 22:03:24 China time on October 2, about 240 seconds. The 80 unique calls consumed 234.79 generation seconds. Per-condition latency includes its logically required calls, so the shared first turn is counted in each two-turn method's cost but deduplicated in actual batch expenditure. Rendering, image preprocessing and decoding are outside the per-call generation timer.

Campus password/key authentication was unavailable to the active runtime. After the interruption the Data volume was mounted successfully; the current CUDA driver was unavailable. CPU inference was sufficient for this small run. These infrastructure limits do not establish GPU-training feasibility.

[Portable artifacts](../../experiments/artifacts/formula-pilot-20261002/README.md) include exact inputs, offline references, eight source images, raw predictions/traces, run metadata, hashes and the score table. They contain controlled synthetic material only. Re-evaluate without a model:
