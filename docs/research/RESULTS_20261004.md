# Source recognition and table development diagnostics

Date: October 4, 2026. These are bounded development experiments with untrained Qwen2-VL-2B-Instruct. They do not establish a held-out benchmark improvement, causal attention explanation, or new algorithm. All inspected pages/regions remain development data.

## Image-only formula recognition

All 16 previously selected UniMER sources were transcribed without the initial candidate or any reference. Two fixed pixel-bound settings produced 32 calls. The prompt and candidate presence differ jointly from the prior repair experiment, so this does not isolate anchoring.

| Condition | Native-input exact-proxy fixes / 6 | Matching-input transitions / 10 | Final raster matches / 16 | Rendering failures | Mean input tokens | Mean output tokens | Mean generation seconds |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| Unchanged native parser | 0 | 0 | 10 | 1 initial failure | 0 | 0 | 0 |
| Image only, 200704 upper pixel bound | 0 | 5 | 5 | 1 | 213.81 | 27.06 | 3.72 |
| Image only, 802816 upper pixel bound | 0 | 5 | 5 | 1 | 213.81 | 27.06 | 3.20 |

All 16 paired processor grids and all 16 output strings are identical across settings. Raising the upper bound alone did not increase actual resolution; these data cannot support a resolution-effect conclusion. No call reaches the 128-token cap. Whole-environment normalization of saved responses leaves the counts unchanged. Recognition failure retains the failed recognition rather than rolling back to the native parser; the unchanged parser is a separate baseline. Generation time is CPU model time, not rendering or end-to-end GPU latency.

Zero exact-raster fixes does not mean zero useful content corrections. On `u009`, the native output `\mathrm{0.2-0.8~\Omega\Xi}` becomes `0.2 - 0.8 \, \text{mg}` in the image-only control. This repairs the unit content, but does not reproduce the released reference's bold styling. Conversely, coordinate-tuple responses remain despite explicit instructions against coordinates. Same-renderer raster agreement is not CDM or a general image-fidelity certificate. The existing source/reference annotation concerns remain separately recorded and frozen.

The [portable evidence package](../../experiments/artifacts/image-only-20261004/README.md) contains all fixed calls, processor comparison, source mapping, offline joins and source-hash-matched inference code, without benchmark images or weights.

## Fixed-pair table diagnostic

Four source pages produce 14 frozen inputs: four released-reference controls, four first-digit perturbations, four published demo predictions, and two span perturbations. There are 56 calls, 14 per method, with the same pinned Qwen2-VL-2B snapshot as the formulas, greedy CPU bfloat16 inference, eight threads, pixel bounds 100352–200704 and a 512-token cap. No response reaches that cap. References, variants, correctness scores and reference-derived locations are excluded from inference. The original adapter is frozen: invalid HTML/JSON, unsupported actions and failed renders roll back. No learned visual acceptance gate is present.

All ten published demo records replay both TEDS and TEDS-S to within 1e-12 using unmodified OmniDocBench sources at `f133a71e9e91c3621c7ce8994200a7b394a06eb3`; downloaded source bytes match the pinned Git blob IDs. For the new experiment, current official normalization is applied equally to reference/initial/final markup. Fixed case/page/annotation pairs are retained rather than rematched.

No full rewrite improves any of the four published demo predictions. Their original parser is unidentified, so this is not named-parser transfer evidence. No method repairs either span perturbation. The bounded edit contract cannot express every native error; notably it cannot insert the missing title row in the Birthday Money prediction. An unchanged final string may mean deliberate preservation, a copied proposal, stop, or rejected-output rollback. The high two-image rejection counts therefore do not demonstrate successful visual judging.

### Changes, failures and source/reference disagreements

On `d005`, all three rewrites repair `2 one` to the visible `1 one`. On `d012`, source-only rewrite repairs `$6` to `$5`. The financial table’s source-only rewrites lower reference TEDS on `d001` and `d002`, partly by moving the market values toward the actual image, while leaving shifted values, wrong units and duplicated labels. Reference-score loss here cannot be equated with pure visual harm.

The JSON editor produces five stop actions, three accepted cell edits and six schema failures. Its accepted edits all have wrong addresses: `d002` writes the already wrong shareholding text over the industry label; `d003` writes a website over that label; `d009` changes the merged company-rating label `公司评级` to `谨慎推荐`. In the last case TEDS remains 0.892857 and TEDS-S remains 0.928571 despite a visibly harmful change. This is a concrete reason to audit edit targets and preservation alongside aggregate metrics.

Three rating-table JSON outputs copy/translate the schema placeholder as `正确普通细胞文本` and return three semicolon-separated actions. Three Birthday Money outputs add an unexpected `value` field and target row 1/cell 0, which is a column label in those inputs. Rewrite failures commonly return `...`, a `Current OCR table:` prefix, or incomplete HTML. Do not loosen the adapter after seeing labels and describe it as the original experiment.

The pre-inference audit records disagreements on two sources. The financial source shows `www.csrbank.com`, 11 rows and market values 196/189; the released reference has `www.csrcbank.com`, an extra blank market-value row, shifted values and repeated debt-ratio labels. Both avoid-rating rows in the rating-table source appear to use `涨幅5%以上`; the released reference uses `跌幅5%以上`. Literal image fidelity takes precedence over semantic plausibility in the observational audit, while released labels and scores remain frozen. No material transcription disagreement was observed for the handwritten number/word and Birthday Money crops.

All four source crops and 14 initial renders were inspected before inference; all 14 final contact sheets were inspected afterward. Source polygons are used directly. Two pages have swapped declared width/height metadata, but the polygons fit the actual images and the intended crops are complete; no coordinate rescaling occurs. Separate pre/post audits preserve observations without relabeling. The [table evidence package](../../experiments/artifacts/table-development-20261004/README.md) includes raw calls, scores, fixed labels, source hashes, inference code and audit notes, without page/crop images or weights.

## Research decision after these diagnostics

These results test prerequisites with an untrained small model; they do not invalidate formula/table repair, distillation or RL in general. They do invalidate using this prompt’s controlled-error repairs as sufficient evidence to scale the current recipe. Measure proposal generation, localization/addressing, acceptance and correct-input preservation separately. Keep all five ideas active at different stages:

| Idea | Evidence now | Next required evidence |
| --- | --- | --- |
| Formula/table repair | Controlled digit repairs; no native formula exact-proxy fixes; no table span repair | Better source grounding and measurable local/native fixes with preservation |
| Agentic RL | Loop software exists; no learned policy or matched-budget training result | A functioning SFT baseline and reward audit before bounded SFT-versus-RL training |
| Selective verifier/cascade | Agreement gates preserve some formula inputs by sacrificing repairs; aggregate TEDS can miss a harmful cell edit | Proposal/acceptance labels and risk-versus-coverage/cost measured on untouched data |
| Small-model distillation | Untrained 2B errors identify candidate training needs | Licensed train/dev-only teacher or local trajectories, quota verified, then held-out net repair |
| Parser transfer | One identified formula parser; table demo parser unknown | A second identified parser, fixed errors/full inputs, and a parser held out from tuning |

A useful next engineering ablation is to append a cell-address map computed only from the initial HTML, retaining the same one-action contract and a fresh original-prompt comparator. This tests whether supplying explicit DOM addresses helps the model’s executable edits. It does not supply a reference-derived target, and cannot establish novelty or isolate internal attention. Freeze the prompts, model, adapter and call budget before inference; retain all 14 development cases and count schema failures, wrong-location changes, stops, repairs, regressions and actual cost. Future scientific evaluation still needs native outputs from a second identified parser, official formula metrics and untouched pages.

The prior-art check already finds overlapping rendering, executable edits, localization, preservation, iterative refinement and training components. Novelty remains unproven; choose a paper contribution only after a specific mechanism outperforms relevant comparators under a common data/model/budget setup.
