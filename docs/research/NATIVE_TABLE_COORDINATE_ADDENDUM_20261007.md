# 原生表格坐标兼容性追加协议

2026-10-07，在第二次完整32源推断前冻结。第一次按当前作者代码运行的输出和评分原样保留，但作为接口兼容性异常，暂不用于学生修复训练或算法增益主张。

## 已确认的原因

原运行结构TEDS-S为0.98936，内容TEDS仅0.41178，文本被集中到前两行。OCR文本本身可读，但结构预测框的纵坐标普遍超出矮宽源图边界。

当前标准SLANet配置在resize/padding前调用`TableBoxEncode`；它按原图宽/高归一化xyxy。当前`TableLabelDecode._bbox_decode`却乘padding宽高、再除resize ratio。非方形图像中，短轴被拉伸至长轴的尺度。无GT的构造往返已用作者真实两个类复现：50×200图上的框[20,10,100,35]编码为[0.1,0.2,0.5,0.7]，当前解码得到[20,40,100,140]，不是原框。

读取日期2026-10-07的[作者commit ac5313d](https://github.com/PaddlePaddle/PaddleOCR/commit/ac5313d0b18e3028b87522c139cc87845091df69)显示，解码器在2024-09-13增加了padding/ratio计算；父commit为`284a20bf10f2754e0c8b361ed27474be1371b746`，其旧分支直接乘原图宽高。本次结论限定当前标准SLANet配置及这组英文导出权重，不推广到所有SLANet变体或其他训练坐标约定。

## 第二条件

保持同32源、权重、字典、CPU环境、检测/识别/匹配代码和其他参数。新增显式`box_decode=original_frame_compatibility`，只将结构框解码恢复为乘原图宽/高；保留float32 dtype，不排序、裁剪或根据参考调整框。它是可审计的运行时兼容性覆盖，**不能称整个作者算法未经改动**。

覆盖在模型初始化后绑定到标准`TableLabelDecode._bbox_decode`；非标准SLANet/未知decoder拒绝覆盖。run receipt和配置记录该事实，driver/helper源码另冻存。横图、竖图、非法尺寸和非有限框的CPU测试先失败后通过；同时在独立Paddle环境验证真实作者encoder加覆盖的往返。

这是由程序不变量和原始代码历史决定的修正，不是遍历缩放系数挑选TEDS最优值。第二条件无GT推断完成后，再用相同官方metric评价全部32源。原异常条件不删除、不与修正条件混在一起，不将它们的差值当作Qwen/SFT/教师/RL贡献。初次训练源smoke仅检查接口可运行，未验证坐标往返；本追加检查补上这一缺口。
