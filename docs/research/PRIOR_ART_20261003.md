# Primary-source novelty check, 2026-10-03

Primary sources were checked again on October 4, 2026: the AAAI publisher page for LATTE, the explicitly linked arXiv versions for OCR-EDR/DEC/ViCoR, and the arXiv records for position bias and Order Matters. This is a version-bounded check, not a claim to have searched every current release. This check changes which claims are supportable. Author-reported results below have not been reproduced by this project. The list is relevant prior art, not an exhaustive novelty search.

| Work | Already demonstrated or proposed | Consequence for this project |
| --- | --- | --- |
| [LATTE, AAAI 2025](https://ojs.aaai.org/index.php/AAAI/article/view/32422), [author code](https://github.com/lt-asset/Latte) | Iterative formula **and table** recognition refinement, rendered delta-view feedback and fault localization. The repository releases generation/refinement outputs. | Table/formula specialization and local visual-difference feedback are not sufficient novelty. Use LATTE as a comparator where its output/data format fits. |
| [OCR-EDR v1](https://arxiv.org/html/2609.03445v1), September 3, 2026 | Source/prediction/render state, preservation of equivalent outputs, executable edits, curriculum SFT, GRPO and cross-parser formula refinement. | The original H2 and H5 ingredients already appear in the base paper. Improvements must be shown at fixed model/data/inference budgets and with preservation measured. |
| [From Diagnosis to Correction / DEC](https://arxiv.org/html/2608.09842v1), August 2026 | Table correction over frozen parsers with decomposition/enhancement, a visual consistency gate, an independently trained ranker and rollback. It reports parser/controller transfer and routing costs. | A table gate plus render-repair loop with rollback is already a close comparator. A small controller is useful engineering, but needs a new mechanism or compelling quality/cost frontier for a strong paper. |
| [Identifying and Mitigating Position Bias, CVPR 2025](https://arxiv.org/abs/2503.13792) | Multi-image position bias and a training-free attention intervention. | Our image-order diagnostic is an OCR-specific implementation/control finding. Do not present position bias itself as a discovery. |
| [Order Matters](https://arxiv.org/abs/2410.16983), October 22, 2024 | Multimodal input-order sensitivity and using informative positions. | Source-last prompting alone is not a new algorithm. A preservation-aware decision mechanism would need a stronger comparison. |
| [ViCoR](https://arxiv.org/html/2609.33603v1), September 27, 2026 | In molecular structure recognition, repair before rejection, spatially aligned rendering and executable graph edits with a progressively trained verifier/reviser. | It concerns chemistry rather than formula/table OCR, but overlaps the general reliability-control idea. Distinguish our task and mechanism explicitly instead of claiming a universal new repair paradigm. |

A secondary search snippet attached ViCoR to the wrong arXiv identifier, `2609.33758`. Opening that primary page showed a different document-restoration paper. The correct ViCoR identifier is `2609.33603`; only the corrected primary source supports this note.

## Decisions

1. Keep the five hypotheses as testable engineering/research questions. Do not call their combination a novel contribution yet.
2. Separate three failures: an inferior proposal, an incorrect acceptance decision, and an unnecessary edit to a correct output. A single aggregate repair score conceals these differences.
3. Examine whether source-grounding sensitivity predicts harmful edits **on development data** before designing a new controller. Any gate selected using tonight's images must be evaluated later on untouched samples and native errors from another parser.
4. Compare order disagreement, a source-only baseline, a learned visual verifier, and independent ranking under matched costs. Order disagreement is a candidate diagnostic signal, not a correctness certificate.
5. Retain table evaluation as required scope. Formula evidence from tonight does not validate table cell content, spans, row/column structure, or official TEDS.

A credible direction to investigate is a small repair policy that learns when available evidence supports a bounded edit, with explicit preservation and abstention under evidence conflict. Novelty is **unproven**: the works above already cover much of the surrounding design. First quantify a failure that existing comparators leave unresolved, then choose the mechanism.
