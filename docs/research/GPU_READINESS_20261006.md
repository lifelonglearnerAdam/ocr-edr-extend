# 单卡训练可行性检查

日期：2026-10-06。通过校园 VPN 和用户建立的共享 SSH 连接，选择 `.161:223` 的 `zmzeng` 账号作为当前科研机器。该机有 8 张 RTX 4090；检查时每张卡约 24 GB 显存，GPU 利用率均为 0%。本次只使用 GPU 0。

- 独立项目：`/data/zmzeng/projects/ocr-edr-extend`。
- 独立环境：`/data/zmzeng/envs/ocr-edr-sft/bin/python`，Python 3.12.15、PyTorch 2.6.0+cu124、Transformers 4.57.1、PEFT 0.17.1、Accelerate 1.10.1。
- 驱动 550.142，使用 CUDA 12.4 的预编译软件栈。实测 bfloat16 矩阵计算及后续训练检查均成功，未调整系统驱动。
- 数据：`/data/zmzeng/datasets/ocr-edr-extend/supervision-20261006`，384 条 train、96 条 dev 监督记录；传输后核验了冻结数据文件哈希。
- 模型：Qwen2-VL-2B-Instruct，固定 revision `895c3a49bc3fa70a340399125c650a463535e71c`；12 个缓存文件在加载前逐一核验字节数和 SHA-256。

这台服务器的 CUDA 栈与前期 CPU 推理环境不同，不能将本次运行当作前期输出的精确重放。服务器基础测试运行 80 项，未失败，15 项可选渲染/官方评测集成检查跳过；本地完整环境的 80 项无跳过验证另有记录。

## 检查范围与结果

使用被冻结 train 清单最前面的保持/受控错误样例，共 2 个样例、1 个源图；dev 不进入优化器。LoRA 只训练语言模型的 q/v 投影，r=4、alpha=8、dropout=0、lr=1e-4，随机种子 20261006。对两个样例的平均 loss 做一次优化器更新，不保存 checkpoint。

两次 loss、LoRA 梯度均有限。优化器只含适配器参数，冻结基础参数没有梯度；检查的 4 个冻结权重片段保持不变，56 个适配器张量发生更新。时间窗口不包含包安装、模型传输、模型文件哈希核验和数据预处理，不是完整科研流水线时延。调用顺序固定，首个批次还受内核初始化和预热影响，两个批次的耗时不能用来比较保持与修复任务的难度。

该检查证明短序列、小批量、单卡 LoRA 训练路径可执行。它不证明修复效果、全数据收敛、长序列显存上限或泛化性能。临时适配器更新未保存，项目尚无此次训练产生的可评估 checkpoint。
