# SFT 源图置换开发诊断

日期：2026-10-06，置换模型调用前冻结。这个诊断检查训练后的 proposer 是否对源图变化有行为响应，而不是证明注意力机制、视觉正确性或额外训练增益。

输入为已冻结的96条开发候选，使用`all`终态192-step checkpoint。保留每条 sample/family ID、当前OCR、文字提示、decoder、预算；源图在32个family之间循环置换。先以`SHA256(20261006-source-swap:<family_id>)`固定排序，然后每族替换为下一族源图，同族3变体使用同一新源图。无标签、分数或模型输出参与置换选择；禁止固定点，禁止重选有利配对。

使用现有source-only runner、greedy、256新token、同一固定checkpoint及实际图片grid/token记录；全96条保留。它是故意源/候选冲突的输入，不是真实parser错误分布。与原始all调用比较raw输出、格式状态、候选拷贝、token成本及图像hash变化。

离线报告源图响应率，并分开统计“答案与原源参考”及“答案与置换源参考”的保守字符串关系。只做开发诊断，不能把对原参考分数降低描述为方法退化，因为源图已改变、原参考不再对应当前任务。若响应率为零，支持在该干预下模型不敏感这一有限观察；若输出改变，仍不证明正确grounding。图像长宽/grid变化会改变输入tokens，不能声称完全匹配token或唯一内部因果机制。

这项额外对照是来源忠实性检查，为后续提议监督与独立验收提供失败类型；不改原始SFT消融的候选、checkpoint或主结果。原实验继续用原源图和冻结参考。
